## `f9e4ce4` v0.1.0: 화면 4종과 깜빡이 누락 판정 엔진

**왜**: 1차 접수(11/15)에서 시연 영상과 GitHub가 가산점이라, 기획서와 화면 시안을 실제로 돌아가는 앱으로 옮겼다. 2차 PT에서 팀이 구조와 로직을 직접 설명해야 해서, 판정 로직은 화면과 분리된 엔진으로 만들고 테스트를 붙였다.

**무엇을**

- `engine/MissedTurnSignalDetector.kt`: 회전 안내(TBT) 후 90초 안에 같은 방향으로 회전했을 때, 회전 직전 10초 안에 같은 방향 깜빡이가 켜졌는지 판정. 안내 없는 회전은 판정하지 않는다. 오래운전과 같은 코드다.
- `engine/FocusCurve.kt`: 6시부터 24시까지 1시간 단위 놓침 비율로 하루 집중 곡선을 만든다. 지금부터 3시간의 놓침 비율이 본인 평소의 1.5배 이상이면 "흐트러지는 시간"으로 본다. 요일 x 시간대 6칸 주간 지도는 놓침 15%와 30%를 기준으로 나눈다.
- `engine/VehicleSignalSource.kt`: 신호 공급원 인터페이스와 시연용 3주치 주행 `DemoSignalSource`. 오전 출근길은 안정적이고 저녁 퇴근길(18~21시)에 깜빡이를 자주 놓친다.
- `ui/`: 출발할 때(집중 곡선과 도움 모드), 주행 중(회전 안내, 100m 앞 깜빡이 알림, 생각 주차장), P단에 넣었을 때(메모 돌려주기, 내리기 전 확인), 이번 주 집중 지도(가로 2칸 대응). 주간/야간 모드는 차량 설정을 따른다.

**확인**: 단위 테스트 6개 통과. 휴대폰 에뮬레이터에서 화면 4종 확인.

**처음 빌드에서 고친 것**

- Asta Sans 가변 글꼴을 `res/font` 로 넣으면 굵기가 적용되지 않아 `assets` + `FontVariation` 으로 바꿨다.
- 시연 데이터의 저녁 운전이 모두 19시에만 있어 18시 기준 판정이 "안정적"으로 잘못 나왔다. 판정을 3시간 단위로 바꾸고 출퇴근 시각을 흩었다.
- 창보다 내용이 긴 화면(P단, 주간 지도)은 스크롤되게 했다.

## `8d0bd48` 지나친 갈림길 판정 추가, 도움 모드 판단을 엔진으로 이동

**왜**: 집중 곡선이 깜빡이 누락 하나만 보고 있었다. 안내받은 회전을 지나쳐 경로를 다시 찾는 일도 흐트러짐의 직접적인 증거다. ADHD 청소년 운전자 실제 도로 연구(2004)가 부주의 실수에 "정해진 회전 지나침"을 넣어 셌고, 약을 먹었을 때 이 실수가 7.8회에서 4.6회로 줄었다. 추가 전에 확인한 것: 휴대폰 내비와 순정 내비는 지나치면 경로를 다시 찾아 줄 뿐, 이를 본인의 시간대별 패턴으로 모아 보여주는 기능은 찾지 못했다. 또 README에 "도움 모드 판단은 화면에서 계산하며 엔진으로 옮길 예정"이라는 숙제가 남아 있었다.

**무엇을**

- `engine/DriveSignal.kt`: `ReRouted` 신호(`onReRouteEnded`)와 `TurnResult.passed` 추가.
- `engine/MissedTurnSignalDetector.kt`: 안내 후 90초 안에 회전 없이 경로를 다시 찾으면 지나침. 깜빡이는 켜지 않은 것(`signalled = false`)으로 기록해 놓침 비율에 그대로 들어간다. 안내 없는 재탐색, 안내대로 돈 뒤의 재탐색, 90초가 지난 재탐색은 세지 않는다.
- `engine/FocusCurve.kt`: `suggestHelpMode(hour)`로 도움 모드 판단을 옮겼다(3시간, 1.5배). 화면에 쓸 `signalMissCount`, `passedCount` 추가.
- `engine/VehicleSignalSource.kt`: 시연 데이터의 저녁 퇴근길 회전 10%를 지나침으로. 지나침은 별도 난수로 뽑아 기존 깜빡이 기록과 시연 영상 속 숫자가 바뀌지 않게 했다.

**확인**: 테스트 10개 추가(지나침 4, 집중 곡선 6), 총 16개 통과.

**도중에 고친 것**: 처음에는 낮 시간에도 지나침을 2% 넣었는데, 주간 지도의 칸이 작아 한 번만 생겨도 아침 칸이 "자주 흐트러짐"으로 바뀌었다. "아침은 안정적"이라는 시연 흐름과 맞지 않아 지나침은 저녁에만 생기게 했다.

## `395bbd4` 도움 모드 효과 비교 엔진

**왜**: 도움 모드를 권하기만 하고, 켰을 때 실제로 나아졌는지는 보여주지 않았다. 본인 기록으로 효과를 확인할 수 있어야 계속 켤 이유가 생긴다.

**무엇을**: `FocusCurve.helpEffect(hours, helpDays)`. 같은 시간대에서 도움 모드를 켠 날과 끈 날의 놓침 비율을 따로 센다. 원인이나 약효는 추정하지 않는다. 시연 데이터는 마지막 4일(11/2~11/5)에 도움 모드를 켰다고 두고, 그날 저녁은 놓침 12%·지나침 없음으로 가정했다.

**도중에 고친 것**: 처음에는 켠 날 놓침을 15%, 지나침을 평소의 30%로 두었다. 그런데 하루 4~6번뿐이라 운 나쁜 날(11/3, 4번 중 4번)이 섞여 켠 날 37%, 끈 날 51%로 차이가 흐렸다. 가정을 위처럼 분명하게 바꿔 16% 대 51%가 됐다.

**확인**: 테스트 3개 추가, 총 19개 통과.

## `ce20855` P단에서 세운 자리 남기기, 주간 화면에 도움 모드 효과

**왜**: 물건 둔 곳을 잊는 일은 성인 ADHD 자가보고 척도(ASRS)에도 있는 문항이다. 마이현대 주차 위치 확인은 GPS 기반이라 수십~수백 m 오차가 날 수 있고, 층 정보를 남기는 기능은 찾지 못했다. 기어 상태를 아는 차는 주차한 바로 그 순간에 물을 수 있다.

**무엇을**

- P단 화면: "몇 층 어디에 세우셨어요?" 아래 "말로 남기기"(시연은 버튼, 실제로는 TTS 질문과 STT). 기본은 다음 시동 때까지 차에만 남기고, "휴대폰으로 보내기"는 본인이 눌렀을 때만 보낸다. 실제 전송 방식은 Pleos 에뮬레이터에서 확인해야 한다.
- 이번 주 화면: "도움 모드로 달린 날 4일" 대신 "퇴근길 놓침, 도움 모드 켠 4일 16%"와 "끈 날 51%".
- 시연 데이터가 바뀌어 출발 화면 숫자도 바뀌었다: 오전보다 5배, 깜빡이 놓침 26번, 지나친 갈림길 5번.

**확인**: Pleos 앱 창 크기 에뮬레이터에서 P단 화면과 주간 화면(가로 2칸)을 확인하고 스크린샷 3장을 다시 찍었다.

## v0.4.0 디자인: 밤 충전소

**왜**: 집중잔량·오래운전·니어바이 세 앱이 같은 남색·모래색·픽셀 칸이라 서로 구분이 안 됐다. 현대차 광고에서 앱마다 장면 하나를 잡았고, 집중잔량은 "밤낚시"(아이오닉 5, 밤 충전소, 차가 나오지 않는 사람 이야기)로 정했다.

**무엇을**

- 야간 팔레트: 바탕을 Hyundai Blue(#002C5F)보다 깊은 #00193A로. Active Blue는 "지금"과 주요 버튼에만.
- 출발 화면 곡선: "불이 많이 켜질수록 자주 놓친 시간" → "칸이 많이 찬 시간일수록 잘 따른 시간"(충전 잔량). 빈 칸은 테두리만, 지금부터 3시간은 Active Blue. 판정 값(`barHeights`)은 그대로, 보여 주는 방향만 뒤집었다.
- P단 화면: 맡겨 둔 생각을 모래색 카드로. "내리기 전에" 카드는 남색으로 바꿔 생각과 차 정보를 나눴다.
- 이번 주 집중 지도: 자주 흐트러진 칸을 빈 충전 칸(Active Blue 테두리)으로. 범례도 "잔량 넉넉 / 조금 줄어듦 / 바닥".
- 캡처용 시작 화면 지정: `adb shell am start -n com.botdue.jipjung/.MainActivity --es screen Parked --ei memos 3`.

**확인**: 테스트 19개 통과. Pleos 앱 창 크기 에뮬레이터(야간)에서 네 화면을 다시 찍고, 차 안 목업 4장을 다시 만들었다. 시연 영상은 아직 v0.3.0 화면이다.

## 2026-11-14 v0.6.0: 약물운전 개정법 대응과 HMI 평가 반영

**왜**

- 팀원 피드백: ADHD 약을 먹고 운전하는 것이 약물운전으로 판정될 수 있다. 2026-04-02 시행 개정 도로교통법으로 약물운전 처벌이 강화됐고 메틸페니데이트도 해당한다. 기준은 "정상 운전을 못 할 우려가 있는 상태"다. 그런데 화면에 "약 먹은 뒤 기준" 보기가 기본으로 보였고, README 배경도 "아침에 먹은 약의 효과가 떨어지는 시간"처럼 약효를 앞세웠다. 앱이 약을 관리하거나 운전 가능 여부를 판단하는 것처럼 읽힐 수 있었다.
- 차량 HMI 디자이너 평가 6.5/10. 주행 화면이 내비 회전 안내(화살표+거리)를 그대로 되풀이해 "내비랑 뭐가 다르냐"는 인상, 주행 중 화면의 "P단에 넣기" 버튼은 터치로 할 수 없는 동작이라 오해, 주간 지도는 "바닥"이 빈 테두리이고 "운전 안 함"이 어두운 채움이라 거꾸로 읽힘, P단 화면 아래가 잘림.

**무엇을**

- 입장: 약을 관리하지도, 약 없이 운전하게 하지도 않는다. 운전 기록으로 본인이 돌아보게 돕고 판정하지 않는다. 고지 문구 세 가지를 `ui/Notices.kt` 한곳에 모았다(화면과 TTS가 같은 문장).
- 주간 지도: "약 먹은 뒤 기준" → "복용 시각 기준", 기본 꺼짐. 켜는 곳에 저장 위치·지우기·법적 한계 고지, 켠 뒤에는 "복용 시각 기록 지우고 끄기". 화면 아래에 앱 범위 고지(처방한 의사와 상의).
- 출발: 도움 모드 제안에 "몸이 평소와 다르면 운전을 미루거나 쉬어 가세요." 링 가운데를 "지금 18~21시 / 흐트러지기 쉬운 시간"으로 결론부터.
- 주행: 남은 거리 링을 640에서 200(시안 px)으로 줄여 오른쪽 위 보조로. 자막 "지금 오른쪽 깜빡이를 켜세요"를 화면 가운데 흰색 104(69sp)로. "오른쪽으로 도세요" 제거. 버튼 2개를 지우고 음성 힌트 한 줄만. 시연 조작은 숨은 방법(힌트 줄 누르기 = 메모, 길게 누르기 = P단).
